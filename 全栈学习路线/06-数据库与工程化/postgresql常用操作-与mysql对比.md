# PostgreSQL 常用操作手册（与 MySQL 对比）

**适用版本：PostgreSQL 12–17 ／ MySQL 5.7、8.0**

## 1. 概述

PostgreSQL（简称 PG）与 MySQL 都是主流的开源关系型数据库，但设计取向不同：

| 维度 | PostgreSQL | MySQL |
|------|-----------|-------|
| 定位 | 功能完备的对象-关系型数据库，强调标准 SQL 与扩展能力 | 轻量、高并发读写，互联网应用广泛 |
| SQL 标准遵循 | 遵循度高 | 部分遵循，有自己的方言习惯 |
| 复杂查询 | 强（窗口函数、CTE、物化视图、丰富索引类型由来已久） | 8.0 后补齐窗口函数与 CTE |
| 数据类型 | 原生支持 JSONB、数组、UUID、范围、地理类型（PostGIS） | JSON（5.7+）、空间类型（功能较基础） |
| 存储引擎 | 单一存储引擎（heap + 多种索引结构） | 可插拔（InnoDB、MyISAM 等） |
| 默认端口 | 5432 | 3306 |
| 超级用户 | postgres | root |

**一句话总结**：需要复杂查询、强一致约束、丰富数据类型时优先 PostgreSQL；追求生态成熟度、运维简单、读多写多的 Web 场景时 MySQL 依然合适。

## 2. 连接与客户端

### 2.1 命令行连接

```bash
# PostgreSQL：psql 客户端
psql -h 127.0.0.1 -p 5432 -U postgres -d mydb
# 常用参数：-W 强制提示输入密码；-c "SQL" 直接执行一条语句后退出

# MySQL：mysql 客户端
mysql -h 127.0.0.1 -P 3306 -u root -p mydb
```

### 2.2 psql 常用元命令（MySQL 无对应概念）

psql 内置大量以反斜杠开头的元命令，是日常运维最高频的工具：

| 元命令 | 作用 | MySQL 中近似做法 |
|--------|------|------------------|
| `\l` | 列出所有数据库 | `SHOW DATABASES;` |
| `\c dbname` | 切换数据库 | `USE dbname;` |
| `\dt` | 列出当前 schema 的表 | `SHOW TABLES;` |
| `\d table` | 查看表结构（含索引、约束） | `DESCRIBE table;` |
| `\du` | 列出用户/角色 | `SELECT user FROM mysql.user;` |
| `\di` | 列出索引 | `SHOW INDEX FROM t;` |
| `\dn` | 列出 schema | 无对应（MySQL 无 schema 层） |
| `\x` | 切换扩展显示模式（竖排） | `\G` 结尾 |
| `\i file.sql` | 执行 SQL 脚本 | `source file.sql` |
| `\q` | 退出 | `exit` |
| `\?` / `\h` | 元命令帮助 / SQL 语法帮助 | `help` |

### 2.3 服务管理

```bash
# PostgreSQL（systemd 环境）
systemctl start postgresql
systemctl stop postgresql
systemctl status postgresql
# 也可用 pg_ctl（以 postgres 系统用户执行）
pg_ctl -D /var/lib/pgsql/data start

# MySQL（systemd 环境）
systemctl start mysqld     # Debian/Ubuntu 上服务名为 mysql
systemctl stop mysqld
mysqladmin -u root -p status   # 查看状态
```

## 3. 数据库与 Schema 管理

### 3.1 层级结构差异

- MySQL：服务器 → 数据库（database）→ 表。database 与 schema 是同义词。
- PostgreSQL：服务器 → 数据库（database）→ schema → 表。一个数据库内可以有多个 schema（类似命名空间），默认是 `public`。

### 3.2 数据库操作对比

| 操作 | PostgreSQL | MySQL |
|------|-----------|-------|
| 创建数据库 | `CREATE DATABASE mydb;` | `CREATE DATABASE mydb DEFAULT CHARSET utf8mb4;` |
| 指定编码 | `CREATE DATABASE mydb ENCODING 'UTF8';` | 建库时指定字符集 |
| 删除数据库 | `DROP DATABASE mydb;` | `DROP DATABASE mydb;` |
| 切换数据库 | `\c mydb`（psql） | `USE mydb;` |
| 查看当前库 | `SELECT current_database();` | `SELECT DATABASE();` |

注意：PG 中 `DROP DATABASE` 不能在有活动连接时执行，需先断开连接；MySQL 8.0 同理。

### 3.3 Schema 操作（PG 特有）

```sql
-- 创建 schema
CREATE SCHEMA app;
-- 在指定 schema 下建表
CREATE TABLE app.users (id serial PRIMARY KEY, name text);
-- 查询时带 schema 前缀
SELECT * FROM app.users;
-- 设置搜索路径（类似默认 schema）
SET search_path TO app, public;
```

## 4. 常用数据类型对比

| 用途 | PostgreSQL | MySQL | 说明 |
|------|-----------|-------|------|
| 小整数 | `smallint` | `SMALLINT` | 相同 |
| 整数 | `integer` / `int` | `INT` | 相同 |
| 大整数 | `bigint` | `BIGINT` | 相同 |
| 自增主键 | `serial` / `bigserial`，或 `GENERATED BY DEFAULT AS IDENTITY` | `INT AUTO_INCREMENT` | PG 10+ 推荐 IDENTITY 语法 |
| 精确小数 | `numeric(p,s)` | `DECIMAL(p,s)` | 相同 |
| 浮点 | `real` / `double precision` | `FLOAT` / `DOUBLE` | 相同 |
| 短字符串 | `varchar(n)` | `VARCHAR(n)` | 相同 |
| 长文本 | `text`（无长度上限） | `TEXT` / `MEDIUMTEXT` / `LONGTEXT` | PG 的 text 无 65535 字节行限制概念 |
| 布尔 | `boolean`（true/false） | `TINYINT(1)`（0/1） | PG 是真正的布尔类型 |
| 日期 | `date` | `DATE` | 相同 |
| 时间戳 | `timestamp` / `timestamptz`（带时区） | `DATETIME` / `TIMESTAMP` | PG 推荐用 timestamptz |
| JSON | `json` / `jsonb`（二进制存储、可建索引） | `JSON`（5.7+） | PG 的 jsonb 查询性能更好 |
| UUID | 原生 `uuid` 类型 | 无原生类型，常用 `CHAR(36)` 或 `BINARY(16)` | PG 优势明显 |
| 数组 | `integer[]`、`text[]` 等 | 不支持 | PG 特有 |
| 网络地址 | `inet` / `cidr` / `macaddr` | 不支持 | PG 特有 |

## 5. 表操作

### 5.1 建表（含自增主键）

```sql
-- PostgreSQL（两种自增写法）
CREATE TABLE users (
    id        bigserial PRIMARY KEY,              -- 写法一：序列
    -- id     bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,  -- 写法二：IDENTITY（推荐）
    username  varchar(64) NOT NULL UNIQUE,
    email     varchar(128),
    status    smallint DEFAULT 0,
    tags      text[],                              -- 数组类型，MySQL 无对应
    profile   jsonb,                               -- 二进制 JSON
    created_at timestamptz DEFAULT now()
);

-- MySQL
CREATE TABLE users (
    id         bigint AUTO_INCREMENT PRIMARY KEY,
    username   varchar(64) NOT NULL UNIQUE,
    email      varchar(128),
    status     smallint DEFAULT 0,
    profile    JSON,
    created_at datetime DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

差异点：

- PG 建表不需要也不能指定存储引擎和字符集（字符集在库级别）。
- PG 的自增底层是序列对象（sequence），可用 `nextval('users_id_seq')` 手动取值。
- PG 中字符串比较默认区分大小写；MySQL 取决于排序规则（collation）。

### 5.2 修改表结构

两者 `ALTER TABLE` 语法高度一致：

```sql
-- 添加列
ALTER TABLE users ADD COLUMN phone varchar(20);
-- 删除列
ALTER TABLE users DROP COLUMN phone;
-- 修改列类型：语法有差异
ALTER TABLE users ALTER COLUMN email TYPE text;          -- PostgreSQL
ALTER TABLE users MODIFY COLUMN email text;              -- MySQL
-- 重命名列
ALTER TABLE users RENAME COLUMN email TO email_addr;     -- 两者都支持
-- 重命名表
ALTER TABLE users RENAME TO members;                     -- 两者都支持
```

### 5.3 删除与清空

| 操作 | PostgreSQL | MySQL |
|------|-----------|-------|
| 删除表 | `DROP TABLE users;` | `DROP TABLE users;` |
| 存在才删除 | `DROP TABLE IF EXISTS users;` | `DROP TABLE IF EXISTS users;` |
| 清空数据 | `TRUNCATE TABLE users;`（可加 `RESTART IDENTITY` 重置序列） | `TRUNCATE TABLE users;` |

## 6. 数据增删改查

### 6.1 插入 INSERT

```sql
-- 单行插入（语法相同）
INSERT INTO users (username, email) VALUES ('alice', 'alice@example.com');

-- 批量插入（语法相同）
INSERT INTO users (username, email) VALUES
    ('bob', 'bob@example.com'),
    ('carol', 'carol@example.com');
```

### 6.2 UPSERT：插入或更新（高频差异点）

```sql
-- PostgreSQL：ON CONFLICT 子句
INSERT INTO users (username, email)
VALUES ('alice', 'new@example.com')
ON CONFLICT (username) DO UPDATE
SET email = EXCLUDED.email;

-- MySQL：ON DUPLICATE KEY UPDATE
INSERT INTO users (username, email)
VALUES ('alice', 'new@example.com')
ON DUPLICATE KEY UPDATE email = VALUES(email);
```

PG 的 `ON CONFLICT` 必须指明冲突列或约束名，还可 `DO NOTHING` 直接忽略冲突；MySQL 依赖任意唯一键冲突。

### 6.3 更新与删除

```sql
-- UPDATE（基础语法相同）
UPDATE users SET status = 1 WHERE username = 'alice';

-- DELETE（基础语法相同）
DELETE FROM users WHERE status = 0;
```

### 6.4 带 RETURNING 的写操作（PG 特有）

PG 的 INSERT/UPDATE/DELETE 支持 `RETURNING` 直接返回受影响行，MySQL 无此能力：

```sql
-- 插入后立即拿到自增 id，无需第二次查询
INSERT INTO users (username) VALUES ('dave') RETURNING id, created_at;

-- 更新并返回旧值/新值
UPDATE users SET status = 2 WHERE id = 1 RETURNING *;

-- 删除并返回被删记录（可用于归档）
DELETE FROM users WHERE status = 0 RETURNING *;
```

MySQL 中获取刚插入的自增 id 用 `LAST_INSERT_ID()`；PG 对应 `lastval()` 或 `currval('users_id_seq')`。

### 6.5 查询与分页

```sql
-- 分页：两者都支持 LIMIT ... OFFSET
SELECT * FROM users ORDER BY id LIMIT 10 OFFSET 20;
-- MySQL 还支持简写，PG 不支持
SELECT * FROM users ORDER BY id LIMIT 20, 10;   -- 仅 MySQL
```

### 6.6 模糊查询与大小写

```sql
-- 大小写不敏感的模糊匹配
SELECT * FROM users WHERE username ILIKE '%ALICE%';        -- PG：ILIKE 原生支持
SELECT * FROM users WHERE LOWER(username) LIKE '%alice%';  -- MySQL：需函数或 ci 排序规则
```

## 7. 高级查询特性

| 特性 | PostgreSQL | MySQL |
|------|-----------|-------|
| 窗口函数 | 长期支持（`ROW_NUMBER() OVER (...)` 等） | 8.0+ 支持 |
| CTE / 递归 CTE | 长期支持（`WITH RECURSIVE`） | 8.0+ 支持 |
| 物化视图 | 支持（`CREATE MATERIALIZED VIEW` + `REFRESH`） | 不支持 |
| 表继承 / 分区表 | 声明式分区（10+），表继承为特色 | 分区表支持 |
| 规则 / 触发器 | 支持，触发器可用 PL/pgSQL 编写 | 支持触发器 |
| 外部表（FDW） | 支持，可挂接外部数据源 | 不支持（FEDERATED 引擎有限） |

物化视图示例（PG 特有）：

```sql
CREATE MATERIALIZED VIEW mv_user_stats AS
SELECT status, count(*) AS cnt FROM users GROUP BY status;

-- 数据变化后手动或定时刷新
REFRESH MATERIALIZED VIEW mv_user_stats;
-- 支持并发刷新（需唯一索引）
REFRESH MATERIALIZED VIEW CONCURRENTLY mv_user_stats;
```

## 8. 索引操作

### 8.1 基础语法对比

```sql
-- 普通索引（语法相同）
CREATE INDEX idx_users_email ON users (email);

-- 唯一索引
CREATE UNIQUE INDEX idx_users_username ON users (username);

-- 复合索引
CREATE INDEX idx_users_status_created ON users (status, created_at);

-- 删除索引
DROP INDEX idx_users_email;                  -- 两者都支持（MySQL 也可用 ALTER TABLE ... DROP INDEX）
```

### 8.2 PG 特有的索引能力

| 索引类型 | 适用场景 | MySQL 对应 |
|----------|----------|-----------|
| B-tree（默认） | 常规等值、范围查询 | InnoDB B+ 树 |
| GIN | JSONB、数组、全文检索 | 无直接对应 |
| GiST | 地理数据、范围类型 | 无直接对应 |
| BRIN | 超大表、物理有序数据 | 无 |
| Hash | 等值查询（少用） | 内存引擎支持 |

```sql
-- JSONB 字段建 GIN 索引（MySQL 只能对生成列建索引近似实现）
CREATE INDEX idx_users_profile ON users USING gin (profile);

-- 部分索引（只索引满足条件的行，MySQL 不支持）
CREATE INDEX idx_active_users ON users (username) WHERE status = 1;

-- 表达式索引（对计算结果建索引）
CREATE INDEX idx_lower_email ON users (lower(email));
```

### 8.3 查看索引

```sql
-- PostgreSQL
\d users                       -- psql 元命令，结构+索引一览
SELECT indexname, indexdef FROM pg_indexes WHERE tablename = 'users';

-- MySQL
SHOW INDEX FROM users;
```

## 9. 视图

```sql
-- 创建普通视图（语法相同）
CREATE VIEW v_active_users AS
SELECT id, username FROM users WHERE status = 1;

-- 删除视图
DROP VIEW v_active_users;
```

PG 额外支持可更新视图范围更广，以及上述物化视图；MySQL 的视图更新限制较多。

## 10. 用户与权限管理

### 10.1 创建用户

```sql
-- PostgreSQL（PG 中 USER 与 ROLE 基本等价）
CREATE USER dev WITH PASSWORD 'secret123';
-- 或
CREATE ROLE dev LOGIN PASSWORD 'secret123';

-- MySQL（账号带主机限定）
CREATE USER 'dev'@'%' IDENTIFIED BY 'secret123';
```

### 10.2 授权

```sql
-- PostgreSQL：授权某 schema 下所有表的只读
GRANT USAGE ON SCHEMA public TO dev;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO dev;
-- 让未来新建的表也自动有只读权限
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO dev;

-- MySQL
GRANT SELECT ON mydb.* TO 'dev'@'%';
FLUSH PRIVILEGES;
```

### 10.3 回收权限与删除用户

| 操作 | PostgreSQL | MySQL |
|------|-----------|-------|
| 回收权限 | `REVOKE SELECT ON ALL TABLES IN SCHEMA public FROM dev;` | `REVOKE SELECT ON mydb.* FROM 'dev'@'%';` |
| 删除用户 | `DROP USER dev;` | `DROP USER 'dev'@'%';` |
| 查看权限 | `\du` 或 `SELECT * FROM information_schema.role_table_grants;` | `SHOW GRANTS FOR 'dev'@'%';` |

关键差异：MySQL 账号是「用户名@主机」组合；PG 用户是全局的，主机级访问控制在 `pg_hba.conf` 配置文件里管理。

## 11. 备份与恢复

### 11.1 逻辑备份

```bash
# PostgreSQL：pg_dump
pg_dump -U postgres -d mydb -F c -f mydb.dump        # 自定义压缩格式（推荐，可并行恢复）
pg_dump -U postgres -d mydb -F p -f mydb.sql         # 纯 SQL 文本
pg_dumpall -U postgres -f all.sql                    # 备份所有库及全局对象（用户、表空间）

# MySQL：mysqldump
mysqldump -u root -p mydb > mydb.sql
mysqldump -u root -p --all-databases > all.sql
```

### 11.2 恢复

```bash
# PostgreSQL
pg_restore -U postgres -d mydb --clean mydb.dump     # 恢复自定义格式
psql -U postgres -d mydb -f mydb.sql                 # 恢复纯 SQL 文本

# MySQL
mysql -u root -p mydb < mydb.sql
```

### 11.3 备份方式总览

| 方式 | PostgreSQL | MySQL |
|------|-----------|-------|
| 逻辑备份 | `pg_dump` / `pg_dumpall` | `mysqldump` / `mysqlpump` |
| 物理备份 | `pg_basebackup`（内置） | Percona XtraBackup（第三方） |
| 增量/归档 | WAL 归档 + pgBackRest 等 | binlog + XtraBackup |
| 时间点恢复（PITR） | 支持（WAL） | 支持（binlog） |

## 12. 日常运维

### 12.1 查看连接与会话

```sql
-- PostgreSQL：查活动会话
SELECT pid, usename, state, query, client_addr
FROM pg_stat_activity
WHERE state <> 'idle';

-- 终止某个会话
SELECT pg_terminate_backend(12345);

-- MySQL：查活动会话
SHOW PROCESSLIST;
SELECT * FROM information_schema.processlist WHERE command <> 'Sleep';

-- 终止某个会话
KILL 12345;
```

### 12.2 查看库表大小

```sql
-- PostgreSQL
SELECT pg_size_pretty(pg_database_size('mydb'));                  -- 库大小
SELECT pg_size_pretty(pg_total_relation_size('users'));           -- 表总大小（含索引）

SELECT relname AS table,
       pg_size_pretty(pg_total_relation_size(oid)) AS total_size
FROM pg_class
WHERE relkind = 'r'
ORDER BY pg_total_relation_size(oid) DESC LIMIT 10;

-- MySQL
SELECT table_schema, table_name,
       ROUND((data_length + index_length) / 1024 / 1024, 2) AS size_mb
FROM information_schema.tables
ORDER BY (data_length + index_length) DESC LIMIT 10;
```

### 12.3 表维护

| 操作 | PostgreSQL | MySQL |
|------|-----------|-------|
| 回收死元组空间 | `VACUUM;` / `VACUUM FULL;` | 无对应（InnoDB 靠 purge 线程） |
| 更新统计信息 | `ANALYZE users;` | `ANALYZE TABLE users;` |
| 重建表/碎片整理 | `VACUUM FULL users;`（加排他锁） | `OPTIMIZE TABLE users;` |
| 重建索引 | `REINDEX INDEX idx_name;` | `ALTER TABLE t DROP INDEX i, ADD INDEX i(...)` |

PG 基于 MVCC 会产生死元组，autovacuum 默认自动运行；若大表膨胀需关注 autovacuum 参数调优。

### 12.4 慢查询与执行计划

```sql
-- 两者都用 EXPLAIN 查看执行计划
EXPLAIN ANALYZE SELECT * FROM users WHERE status = 1;   -- PG：ANALYZE 真正执行并给耗时
EXPLAIN SELECT * FROM users WHERE status = 1;           -- MySQL（8.0 可用 EXPLAIN ANALYZE）
```

```sql
-- 开启慢查询日志
-- PostgreSQL（postgresql.conf）
-- log_min_duration_statement = 1000   -- 单位毫秒

-- MySQL
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;
```

## 14. 从 MySQL 迁移到 PostgreSQL 的注意事项

1. **标识符引用**：MySQL 的反引号 `` ` `` 全部换成双引号 `"`，或直接去掉（PG 未加引号的标识符自动转小写）。
2. **大小写**：PG 未加引号的库名、表名、列名一律折叠为小写；若 MySQL 中混用大小写且依赖它，需统一为小写或全部加双引号。
3. **自增列**：`AUTO_INCREMENT` 换成 `bigserial` 或 `GENERATED BY DEFAULT AS IDENTITY`；迁移数据后要重置序列：`SELECT setval('users_id_seq', (SELECT max(id) FROM users));`
4. **UPSERT 语法**：`ON DUPLICATE KEY UPDATE` 改为 `ON CONFLICT (...) DO UPDATE`，且必须指明冲突列。
5. **布尔与类型**：MySQL 的 `TINYINT(1)` 迁移为 `boolean`；隐式类型转换（如字符串与数字比较）在 PG 中会直接报错，需显式 `CAST`。
6. **函数差异**：`IFNULL` → `COALESCE`；`GROUP_CONCAT` → `string_agg`；`DATE_FORMAT` → `to_char`；`UNIX_TIMESTAMP` → `extract(epoch from ...)`。
7. **存储引擎与字符集**：PG 无引擎概念，字符集在建库时确定（建议 UTF8），无需逐表指定。
8. **权限模型**：PG 权限粒度在 schema/对象级，迁移后要重新设计授权；主机级访问控制通过 `pg_hba.conf` 配置。
9. **迁移工具**：小库可用 `pgloader` 一键迁移；大库建议先迁结构，再用 CSV 或 CDC 工具（如 Debezium）迁数据。
