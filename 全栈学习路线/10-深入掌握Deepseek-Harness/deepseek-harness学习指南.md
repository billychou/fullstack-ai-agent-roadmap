# 11天，16万星：我把 DeepSeek Harness 从原理到生态扒了一遍

> 本文写于 2026 年 8 月 24 日，最新更新版补充了与 Claude Code、Codex、LangChain/LangGraph 的定位对比，并逐一展开了六个深挖方向。DeepSeek Harness 还处在开发者预览阶段，官方明说会有破坏性变更，文中所有命令和版本号请以官方仓库的最新文档为准。这是本系列的深度篇：速览篇讲它是什么，实践篇讲怎么装起来跑，这一篇讲它里面到底有什么、外面长成了什么样、跟整个行业的坐标系对起来看它站在哪。

8 月 13 日深夜，DeepSeek 赶在 V4 Pro 正式版发布的当口，悄悄开源了一个叫 Harness 的项目。

没有发布会，没有预热，就一条仓库链接。结果 11 天过去，这个仓库的 Star 数冲到了 16 万往上，GitHub 上挂着 `dsh-plugin` 标签的仓库从 700 多个涨到接近 8000 个，有人管它叫"赛博乐高"，有人说这是"Agent 领域的 Linux 时刻"。

我花了一周多时间，把官方文档、架构源码、社区插件和几轮版本更新翻了一遍，又把市面上能找到的横向对比、实测报告和安全盘点都过了一遍。这篇就把我看到的都摊开讲：它到底是什么、架构上凭什么被吹成这样、上手要踩哪些坑、生态现在真实长什么样，跟 Claude Code、Codex、LangChain 摆在一起各自站在什么位置，以及这十几天里发生的几件大事背后藏着什么。

## 一、先纠正一个误会：它不是"又一个 AI 编程助手"

很多人第一眼看到 DeepSeek 做了个能写代码的东西，就想当然当成 DeepSeek 版 Claude Code。这是错的，而且错得很关键。

官方给的公式很干脆：

```
Agent = Model + Harness
```

模型负责推理，Harness 负责模型之外的所有工程活：工具怎么注册调度、上下文怎么组装裁剪、会话怎么持久化、代码在哪个沙箱里跑、失败了怎么恢复。用 React 开发者熟悉的话说，大模型是那个纯组件 `<Model />`，只有"渲染"能力；而一个真能干活的智能体，外面还得包一圈工具调用、状态管理、权限沙箱、审批流程——这圈基础设施就是 Harness，直译"马具"，缰绳的意思。

Claude Code、Codex 这些产品，本质是把这层基础设施做成了闭源成品：精装房，拎包入住，但墙不能拆。DeepSeek 这次干的事，是把整栋房子做成了乐高——图纸开源，预制件开源，墙随便拆，零件随便换。

这也是它命名刻意避开 "Code" 的原因。编码只是官方预设的一种插件组合，你完全可以拿它拼一个跟编程毫无关系的智能体。搞清这一点，后面所有架构设计才说得通。

## 二、核心口号只有五个字：一切皆插件

DeepSeek Harness（命令名 `dsh`）的设计哲学就一句："Everything is a Plugin"。

模型适配器是插件，工具注册表是插件，会话日志是插件，沙箱和审批策略是插件，系统提示词是插件，UI 是插件——连 Agent 主循环本身，也是个插件。想换掉主循环？不用 fork 仓库，改一行配置就行。整个系统没有一个"特权核心"需要你去打补丁。

撑起这套东西的底座叫 Cordis，来自 Koishi.js 生态的成熟插件化框架，DeepSeek 以 Vendor 形式锁定了 4.0.x 版本，还配了篇学术论文（这篇论文后面会单独拆）。名字很唬人，拆开说其实是两件事：

**空间可组合性**，管的是"插件之间能不能拼到一起"。插件用 `inject: ['tools']` 声明依赖，运行时负责解析和注入，依赖变了响应式通知。这一层 VS Code 扩展、Webpack loader 都做到了，不算稀奇。

**时间可组合性**，才是真正有意思的部分。它管的是："一个已经生效的插件被拆掉之后，世界能不能恢复成它从没来过的样子。"

这事难在哪？副作用是单向的。一个插件注册了工具、改了系统提示词、订阅了事件流、写了磁盘缓存，`npm uninstall` 撤销不了"它已经做过的事"。VS Code 给扩展提供 `deactivate()` 钩子，靠开发者自觉写清理逻辑，那是工程约定；Cordis 的做法是让每次上下文变换都携带一个逆操作，由运行时强制追踪和执行撤销，这是形式化保证。React 里最接近的类比是 `useEffect` 的 cleanup——但那个忘了写就泄漏，Cordis 把清理做成了运行时不变式。

一句话概括：空间可组合性让积木能拼上，时间可组合性让积木能无痕拆下来。现有的插件生态，几乎都只做了前一半。

这套机制落到产品上，就是三个组合层次：

- **Bundle**：分发格式，一袋预拼好的积木
- **Profile**：命名的插件组合，说明书上的成品图纸，内置 `web`（浏览器应用）和 `headless`（无 UI 单次运行）两个模板
- **Patch**：按 id 整行替换配置，免改源码换组件

应用顺序是 bundle 列序 → profile patch → home 级 patch → `--patch` 命令行覆盖，用 `dsh --profile web --dump-config` 能看到实际启动树。这里有个语义陷阱要提醒：patch 是"替换整行"不是合并，只想改一个字段，也得把那行其余字段全部重述一遍。

## 三、翻完架构，我认为最值得抄的三个设计

撇开插件体系，dsh 还有三处设计，我觉得是任何做 Agent 基础设施的人都该研究的。

**第一个：事件溯源的会话模型。**

这是 dsh 最受赞誉的设计，核心不变式一句话："Model-visible means logged"——凡是模型能看到的，一定能从日志重建出来。
![[Pasted image 20260824170055.png]]

会话日志（追加式的 SessionEvent）是唯一事实源，模型看到的对话历史由 `deriveMessages()` 从日志投影出来；fork、resume、transcript、遥测，全部派生自同一条事件流。好处是天然可回放、可审计、可复现——这对**研究和企业合规**都是刚需。用 React框架 的概念说，这就是把单向数据流推到了极致：日志是 single source of truth，其余都是投影。

配合**上下文自动压缩**和**大输出落盘**，长任务的缓存命中率社区实测大多能稳在 99% 上下。这个数字不是好看的装饰，它直接决定你跑一天任务花多少钱——"缓存经济学"那节会回到这点。

**第二个：权限和沙箱是两套独立体系。**

很多人的认知误区是把这俩当一回事。dsh 里它们各管各的：

权限（permission preset）管审批，三档：`read-only`、`workspace-write`（出厂默认，仅工作区可写加询问）、`danger-full-access`（无审批门，切换要二次确认）。批准策略只有 ask 和 never，授权一次性，无人应答时一律拒绝，fail-closed。

沙箱（真正的文件边界）管隔离，三档：只读、工作区可写、完全放开。Linux 用 Landlock/bwrap，macOS 用 Seatbelt，Windows 用 ACL 受限令牌。

文档里有一句很诚实的话："沙箱只约束诚实代码，不是安全边界。"还有一句：权限限制的是"写"，不是"看"——读取、联网、查进程不受同等限制。把这两句话读进去，你对 Agent 安全的理解就超过大多数人了。有独立评论者进一步点破：dsh 的本地沙箱只限制写入位置，不限制进程可见性和网络出口，保护范围比"沙箱"这个词暗示的要窄。

**第三个：对现有标准全部复用，不另起炉灶。**

Skill 格式与 Anthropic Agent Skills 完全兼容，Claude Code 的技能可以直接拿来用，社区还有一键迁移插件；AGENTS.md / CLAUDE.md 约定照搬；MCP 原生内置客户端，社区桥接插件的工具命名和 Claude Code/Codex 对齐。

区别在哪？这些标准对 dsh 来说是"接入生态的接缝"，它自己的核心扩展机制是进程内的 Cordis 插件——比 MCP 那种外部进程、只接工具的方式深入得多，插件可以直接拦截 Agent 事件流、替换主循环本身。Claude Code 闭源一体化只能叠加不能替换，Cline 受限于 VS Code 扩展体系，LangGraph 的 loop 藏在框架内部——只有 dsh 把每一层都掀开给你看。

顺带说下执行模型的三级词汇：**step** 是一次模型请求加工具调用，**turn** 是零或多个 step 组成的一轮交互，**round** 是外层目标迭代。用户输入也有三级投递：`followup()` 排下一轮，`steer()` 中途打断改方向，`inject()` 只加上下文不唤醒。这些词汇看轨迹面板时会反复遇到。

## 四、上手实录：安装劝退的四个坑，我都替你整理好了

先说环境：Windows/macOS/Linux 都行，Node.js 必须 ≥ 22.19（推荐 24 LTS），内存 4G 起，源码构建要 pnpm ≥ 10。

四种装法：

```bash
# npx 快速体验（无需安装）
npx @deepseek-ai/dsh web          # 打开 http://127.0.0.1:3080

# 全局安装（日常推荐）
npm install -g @deepseek-ai/dsh
dsh web

# 源码（二开/插件开发）
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness && corepack enable && pnpm install && pnpm run build && pnpm dsh web

# Python SDK（自带运行时，无需 Node）
pip install deepseek-harness-sdk
```

API Key 在 Web 界面 Settings → Models 里填，`sk-` 开头，platform.deepseek.com 创建，只在创建时显示一次。密钥明文存在 `~/.dsh/.credentials.yaml`，界面只显示脱敏描述符。

社区总结的"安装劝退"四大主因，做成速查表：

| 症状                                       | 原因                           | 解法                                     |
| ---------------------------------------- | ---------------------------- | -------------------------------------- |
| 刷屏 `EBADENGINE` 或 `parseEnv` 报错          | Node 版本低于 22                 | 装 LTS 后必须重开终端刷 PATH                    |
| `Failed to load native module: pty.node` | 新版 npm 默认禁安装脚本，node-pty 编译被拦 | 加 `--ignore-scripts=false` 重装          |
| Windows C 盘爆满加下载慢                        | npm 缓存默认在 C 盘                | `npm config set cache/prefix` 挪盘，换国内镜像 |
| 端口 3080 被占                               | —                            | `--port 8080`                          |

不会命令行的话，社区出了好几款图形化启动器，Windows 托盘版、Web GUI 版、双击安装包都有。提醒一句：安装包都没签名，SmartScreen 提示未知发布者是正常现象。

装完之后的三步：配模型（填 Key 保存，即时生效）、选工作区（强烈建议新建一个空白专用文件夹，别选桌面和系统盘根目录——最常见的卡点就是不选工作区，输入框一直是灰的）、跑个只读的轻量任务验证，比如让它总结某个目录结构。

还有一个关键认知：终端窗口不能关。终端进程才是 Host，网页只是界面，`Ctrl+C` 会停掉整个服务；会话持久化在 `~/.dsh/sessions`，关页面任务不丢。

**写第一个插件比想象中简单**，一个导出 `apply(ctx)` 的 TypeScript 模块，10 行代码：

```typescript
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context) {
  console.log('[hello-plugin] plugin loaded!')
}
```

本地开发时在插件目录里 `npm init -y`，装上 `typescript`、`@types/node`、`@deepseek-ai/cordis` 这几个依赖，`package.json` 里 `"type": "module"`、`main` 指向入口文件即可。装完刷新 Web 界面自动加载，热插拔不用重启。想注册工具、拦截事件流，都是在 `ctx` 上挂钩子——这就是 Cordis 的 DI 模型。

**写第一个技能更简单，零代码**，一个 Markdown 文件：

```markdown
---
name: csv-report
description: 当用户要求处理 CSV 文件并生成汇总报告时使用。输出为 Markdown 表格。
---

## 操作流程
1. 读取用户指定的 CSV 文件
2. 统计行数、列名、各列缺失值
3. 按第 2 列分组汇总
4. 输出到 ./reports/summary.md
```

技能放项目级 `.dsh/skills/<name>/SKILL.md` 或全局 `~/.dsh/skills/`，同名时项目级覆盖全局。这里有个设计细节值得说：技能不进 system prompt，而是作为用户角色消息前缀注入——每步请求前先给模型一个 `<available_skills>` 摘要，模型匹配到任务后再调工具取正文。这样避免了系统提示词膨胀，跟有些框架把 AGENTS.md 整个塞进系统提示词的做法形成鲜明对比。

写好技能的关键全在 `description`：写清"当用户要求……时使用"这种具体场景，别写功能罗列；正文写操作流程不写原理，定死工具、输出位置、命名规则；一个技能只干一件事。

## 五、生态观察：8000 个插件，和一个被涨价"杀死"的明星项目

先看数据（以下均为 GitHub API 实测或媒体公开口径，截至 8 月 19 日）：

主仓库 165,929 星、17,650 fork，创建于 8 月 13 日 11:56 UTC。首日涨星各媒体口径不一，有说 4.6 万的，有说 6.8 万的；"42 小时破 10 万"刷新 GitHub 纪录，也有媒体表述为 3 天。精确数字没获官方印证，但趋势一致：史上最快。

`dsh-plugin` 标签仓库：8 月 15 日约 700 多个，8 月 19 日实测 7,995 个，四天涨了约 10 倍。社区插件峰值增速 99 个每小时。

但真正让我觉得这个生态"成立了"的，不是数量，是分层。

**生产力这一层**，基本都在补 dsh 发布时的体验短板：`dsh-memory-evolve` 做跨会话长期记忆，能感知 Git 分支、后台演化技能，解决"每次开聊就失忆"；`dsh-agent-teams` 在会话里拉起多 Agent 团队，队长拆任务、设依赖，Web 界面能实时围观谁在干活；Better Sidebar 把文件管理、代码编辑、终端、Git 面板塞进同一个侧边栏，做成迷你 IDE；`dsh-claude-move` 把 Claude Code 的记忆、Skills、旧会话整体迁过来，接着上次的对话继续聊。发布不到三天跨竞品迁移工具就出现了，说明"从 Claude Code 搬家"是真实需求。

**玩具这一层**，电子宠物、像素鲸鱼、十几款 4399 风格小游戏、2005 年中文网站风格的广告 UI、同花顺皮肤（K 线图是 Token 消耗、成交量是代码变更行数）。别小看这些——npm 和 VS Code 插件市场早期，走的全是同一条路：先有一批认真解决问题的，再来一批玩梗的，内容膨胀是平台型生态的必经阶段。

然后是这轮生态里最残酷的一课。

社区标准预设项目 `dsh-anchored-standard`，8 月 14 日创建，不到一天 252 星，8 月 19 日 3,628 星。它给"一切皆插件"带来的配置负担提供了一套研究驱动的答案：会话先在极简工具集下引导，持久化后再提升到完整标准工具集，按需解锁重型工具。

但 8 月 17 日，DeepSeek 官方 API 涨价落地（同时生效的还有峰谷定价：空闲时段价格是高峰的一半）。这个项目依赖的评估循环——多轮探针实验——突然跑不起了，作者宣布停止活跃开发，转入维护模式，另留了一封 FAREWELL.md。

一个 3600 星的生态明星，被一张定价表按下了暂停键。它给所有生态参与者上了第一课：预设、评测、调参这类"评估密集型"玩法，对 token 价格极度敏感。定价分层本身是行业惯例，但它和生态碰撞的后果很残酷：重度依赖评估循环的项目最先失去成本可行性，轻量玩耍的项目几乎无感。"降价引流入场、涨价筛选留存"的节奏，对生态项目是系统性风险。

企业数据接入这边也有个标杆案例：企查查 MCP。OAuth 授权后，Agent 按账号权限调用覆盖 4 亿多市场主体的数据，6 大模块 185 项工具。他们提出的"四重边界"——主体边界、人员边界（防同名误配）、时间边界（现状对历史）、证据边界（AI 不得脑补）——本质是把"查得对"看得比"能查到"更重要，做 Agent 数据接入的都该抄下来。

## 六、这十几天的更新：多模态补齐，Claude Code 变成了"插件"

写这篇的当口，dsh 已经连续发了三个版本，信息量很大，挑重要的说。

**rc.7（8 月 17 日）**：Claude Code 和 Codex 的子代理任务接入 Job Panel 统一管理；MCP/ACP 图片附件持久化，为多模态铺路。

**rc.8（8 月 20 日）**，14 项更新，重点看两块：

多模态正式补齐。DeepSeek 模型适配器可以配置启用原生图片请求，`/goal`、`/plan` 等核心命令支持图文混合输入，输入框 `@` 菜单新增文件和历史会话引用。有个细节很见设计功力：如果当前模型不支持图像输入，Harness 会自动退化到"工具层视觉"——这条降级链路值得单独展开，后面深挖章节细讲。

子代理体系变了。这是 rc.8 最具战略意义的变化：**Claude Code 和 Codex 不再与主体捆绑，改成按需安装的 Profile Bundle，作为子代理被 Harness 调用**。Codex 还新增了非交互权限模式（无人值守跑流程）和多命名实例（同一任务里并存多个不同配置的子代理）。配合子代理结果及时反馈并主动唤醒父任务的机制，dsh 正在从"一个 Agent"滑向"Agent 的统一调度层"。

**v0.1.1-rc.1（8 月 21 日）**：新增视觉模型选项 `DeepSeek-V4-Flash-Vision-Exp`——前一天社区还在猜官方是不是在剧透 V4 视觉版，第二天就实锤了。更重要的是修了一个安全问题：**Bubblewrap 沙箱内受限进程可经 `/proc/<pid>/root` 绕过限制**。在用沙箱跑不可信任务的，建议立即升级。这次逃逸的完整故事，放在安全深挖那节讲。

多模态这里有个最容易踩的坑：Harness 多模态了，不等于你当前用的模型多模态了。默认的 DeepSeek-V4-Pro 是纯文本模型，直接发图会报错——这是有意设计，工具结果要进持久会话历史，路由不支持图片会破坏续聊和分叉。想体验原生看图，切到 `DeepSeek-V4-Flash-Vision-Exp` 并开启原生图片请求配置。

另外两个实用提醒：升级注意 rc.8 的 SQLite 存储结构不兼容旧版，旧会话数据可能读不了；启动 Web UI 建议带上 `--patch` 参数，否则部分插件和技能不生效。

## 七、定位对比：Claude Code、Codex、LangChain 各自站在哪

聊完 dsh 自己，该把它放进整个行业的坐标系里了。这一节回答三个问题：Harness 这个词到底指哪一层？四个名字摆在一起各是什么物种？选型时真正该比的是什么？

### 7.1 先画一张地图：四层技术栈

对比之前必须先纠正一个流行错误。LangChain 官方给 Harness 下的定义是："模型本身之外的全部代码、配置与执行逻辑。"在此基础上，业界已经形成一个四层栈：

| 层级 | 干什么 | 代表产品 |
|---|---|---|
| 模型 | 推理 | DeepSeek V4、Claude、GPT 系 |
| Harness | 运行**单个**智能体：循环、工具、沙箱、记忆、上下文 | Claude Code、Codex、DeepSeek Harness、OpenCode、Goose |
| 框架 | 编排**多个**智能体：显式状态、分支、控制流 | LangChain、LangGraph、CrewAI |
| 平台 | 跨团队跑一堆 Harness：持久执行、成本归因、治理 | 各家 Agent 管理平台 |

分界线一句话：**框架组合智能体，Harness 运行智能体**。LangChain 团队自己也是这么分的——LangChain 是框架，LangGraph 是运行时，DeepAgents 才是 Harness，一家厂商三个产品站在三层上。

所以严格说，"DeepSeek Harness 对比 LangChain"这个问法本身就错位，相当于拿发动机对比整车。但用户实际要做的选型决策是真实的，所以下面还是把两条路线放在一起比，只是比的时候请记住它们不在同一层。

### 7.2 Claude Code 与 Codex：闭源成品路线

先看两张基本盘数据（截至 8 月 19 日）：

| 产品               | 厂商与许可             | 技术栈               | 模型支持          | 星数     |
| ---------------- | ----------------- | ----------------- | ------------- | ------ |
| Claude Code      | Anthropic，专有许可    | TypeScript        | 仅 Anthropic 系 | 142k   |
| Codex            | OpenAI，Apache-2.0 | Rust + TypeScript | 仅 OpenAI 系    | 107k   |
| OpenCode         | Anomaly，MIT       | TypeScript        | 75+ 提供商，含本地模型 | 199k   |
| DeepSeek Harness | DeepSeek，MIT      | TypeScript        | 约 40 家，一切皆插件  | 165.9k |

Claude Code 和 Codex 是一对镜像：都是订阅制托管成品，都把自家模型锁死在核心里。第三方评测对两者的定性一致——闭源、固定、内部逻辑不可见；当模型跑偏、啰嗦、误处理子任务时，用户只能围绕一个打不开的系统调提示词和规则。Claude Code 还有个结构性特点：记忆在设计上做得很薄——这一点后面讲"换 Harness 比换模型更影响结果"时会再出现。

有意思的是一家同时运营七个 Harness 的机构（winder.ai，他们把七个 Harness 都跑在沙箱化桌面里做对照）总结出的用法：把 Claude Code 和 Codex 配对，让它们在同一个任务上互相挑刺——"两个会吵架的智能体，产出的软件好于其中任何一个"。

顺带两个外围产品的警示故事：OpenCode 星数最多（199k），但在 2026 年 3 月的 v1.2.23 之前，它默认把用户的每条提示词发给外部模型用来生成会话标题——哪怕你只配了本地模型；Qwen Code 跑自家 Qwen 模型是"我们用过最贴合的 Harness"，指向其他模型则问题频发。这两个案例说明：开源和多模型支持只是入场券，信任要靠行为攒。

### 7.3 LangChain/LangGraph：它们不是 Harness，但必须比

LangGraph 走的是与 dsh 完全相反的哲学。它把智能体工作流建模成有向图：节点是动作，边是转移，状态流经全图，每一步都存检查点，追求确定性执行。两份哲学声明摆在一起：

- **DSH**：用配置来组合，用可替换的部件搭建智能体
- **LangGraph**：显式状态机，定义每一个转移，靠读代码来调试

LangGraph 的底气来自生产验证：稳定版 1.0 发布于 2025 年 10 月，此前已经在 Uber（路由与物流）、LinkedIn（内容审核）、Klarna（客服自动化）的生产环境跑了一年多。

有一份 47 小时的对照实测值得引用（同一模型 DeepSeek V4 Flash、同一组工具、同一测试集，100 个多步编码任务；注意它基于 dsh 的 rc.6，且是单一来源，看个方向就好）：

| 指标 | DeepSeek Harness | LangGraph | 谁赢 |
|---|---|---|---|
| 单任务平均延迟 | 3.2 秒 | 3.8 秒 | DSH |
| 内存开销 | 180MB | 240MB | DSH |
| 冷启动 | 2.1 秒 | 0.8 秒 | LangGraph |
| 错误率 | 7% | 4% | LangGraph |
| 任务成功率 | 93% | 96% | LangGraph |
| 平均 Token | 约 2400 | 约 2600 | DSH |

结论分层很清晰：**要状态持久化和人机协同，LangGraph 是碾压级的**——检查点机制天然支持故障恢复、暂停等人工审批、时间旅行调试，一个金融合规审批场景，LangGraph 两天做完，DSH 靠自定义插件实现要一到两周。**要运行时可组合性，DSH 是碾压级的**——多品牌多租户场景，DSH 三个配置文件一天搞定，LangGraph 要在图里写运行时分支写三天。30 天生产稳定性测试，LangGraph 正常运行时间 99.4% 对 DSH 的 98.7%，崩溃恢复 30 秒对 8 分钟。

这份实测的作者最后给的判断很克制：四周内要上生产、要人工审批流、受监管行业——选 LangGraph；要多租户白标、要运行时可组合、团队是 TypeScript 栈——选 DSH。他的原话是："DSH 大概率会在 6 到 12 个月内成熟为 LangGraph 的扎实替代品。但'大概率'和'6 到 12 个月'的意思是，现在，LangGraph 才是务实之选。"

### 7.4 换 Harness 比换模型，更影响结果

这是整轮调研里我认为最有价值的一组事实。在模型能力相近的前提下，Harness 的差异对结果的影响，超过模型本身的差异：

- **Vercel**：砍掉一个智能体 80% 的工具，同一模型上成功率从 80% 升到 100%，Token 消耗减半以上，延迟从 724 秒降到 141 秒
- **LangChain**：只换 Harness 不换模型，自家编码智能体在 Terminal Bench 上从 52.8% 提到 66.5%
- **普林斯顿 CORE-Bench**：同一个模型，在两种脚手架下分别拿 42% 和 78%
- **Harvey**：法律智能体的准确率提升了一倍以上，纯靠 Harness 工程
- **最扎心的一个**：Terminal-Bench 2.0 上，第三方产品 Letta Code 跑 Claude Opus 4.5 拿到 59.1%，Anthropic 官方的 Claude Code 跑**同一个模型**只有 41.6%——原因不复杂，这个基准奖励持久记忆，Letta 围绕记忆底座构建，而 Claude Code 的记忆设计偏薄

四个案例都指向同一个结论：模型能力趋同之后，差距来自模型外面那一圈。Raschka 的说法最严谨：在裸模型能力大同小异的前提下，Harness"往往是让某个模型比另一个更好用的那个区分因素"。

这件事对理解 DSH 的意义在于：它开源的正是这一层的完整参考实现。而且 Harness 工程分两种命运——上下文压缩、重试逻辑这类"聪明补丁"会随下一代模型蒸发，是隐藏技术债；但沙箱、权限、消费上限、审计轨迹这类东西编码的是"你的组织允许什么"，任何模型发布都不会废除它们。有人总结得很狠："好的团队攒了一大堆 Harness 工程。苦涩的是，其中几乎全部都会溶解在下一代模型里。"——所以判断一个 Harness 值不值得投入，就看它的投入落在哪一种上。

### 7.5 互操作：它们正在互相收编

最后说清楚这个生态正在发生的融合，这直接影响选型：

**Zed Agent、OpenHands、DeepSeek Harness 都说 ACP（Agent Client Protocol），可以互相驱动**；只要本机装了，DSH 能把 Claude Code 和 Codex 作为子进程跑起来。Linux 基金会 2026 年成立了 Agentic AI Foundation，收编了三笔捐赠：Anthropic 的 MCP（工具标准）、OpenAI 的 AGENTS.md（指令标准）、Goose 本体。

Addy Osmani 的观察很精辟：各家 Harness"彼此之间的相似度，已经超过它们底层模型之间的相似度"。功能清单会过期，趋同正在发生；选型时真正不过期的是三个假设——**你用什么模型**（九款主流 Harness 里，只有两款绑死单一厂商，其余都是模型无关的，但"名字会骗人"：Qwen Code 其实支持多厂商，Codex 其实只跑 OpenAI）；**它跑在哪**（订阅托管，还是沙箱、凭据、审计全由你自己搭）；**谁能改它的行为**（会写 Markdown 的人，还是能部署代码的人——这是伪装成技术选择的组织选择）。

我自己的选型建议收成一句话：开箱即用、企业团队协作，选 Claude Code；审查不可信代码、CI/CD，Codex 沙箱最硬；需要显式状态机和人工审批的复杂流程，LangGraph 是唯一经过生产验证的答案；成本敏感的批量任务、白标定制、二次开发，等 dsh 脱离预览版后它是唯一解。对多数人，眼下最理性的姿势是**双持**：主力工作流留在用惯的工具上，拿 dsh 尝鲜、观察生态，等 API 稳定、分层清晰了再决定迁不迁。还有个实用的经验阈值：当你能用 Markdown 描述的"智能体任务"积累到十个左右，一个 Harness 才开始回本；在那之前，你只是在为运行一两个任务而维护一套基础设施。

## 八、六个深挖方向，逐一展开

上次我列了七个值得深入的方向，这次把其中六个一次讲透。

### 8.1 工具层视觉：纯文本模型怎么"看图"

先做个术语澄清："工具层视觉退化"不是官方术语，检索下来没有权威定义；它实际指向的是 rc.8 引入的多模态降级机制。与之相邻但不同的还有一个概念：极简模式（Minimal）的界面简化——那个模式只保留持久 bash 和文件编辑器两个工具，刻意移除搜索、技能、子代理这些外围机制，用途是模型评测：DeepSeek 官方就是用极简模式跑的 V4-Flash 公开编码基准。设计动机很值得琢磨：现代基准测的往往不止模型，规划器、上下文组装、重试策略都会改变成败，研究者需要一个"去掉大部分环境、只留最小执行面"的条件来观察模型本身。这和视觉降级是两回事，别混。

真正的降级链路是这样的：当你选的模型不支持图像（比如默认的 V4-Pro），直接发图会被拒——这不是缺陷，是有意设计，因为工具结果要进持久会话历史，路由不支持图片会破坏续聊和分叉。此时 Harness 自动切换到工具层视觉：**先做 OCR 识别文字，再统计颜色比例，再扫描像素行，再读取图片元信息**，把一张图拆解成结构化证据，交给纯文本模型推理。

社区插件走的是同一条思路：ModLens 充当"视觉桥"，先把图片的文字、布局、实体整理成结构化证据再交给 DeepSeek 推理；`dsh-vision-toolkit` 提供图片问答、长截图 OCR、UI 还原、像素对比共十个视觉工具。这条链路的意义超出了视觉本身：它演示了 Harness 哲学的核心动作——**把模型层的能力短板，转化为 Harness 层可插拔、可替换、可审计的工程问题**。模型升级了，换掉这个插件就行，架构一行不用动。

### 8.2 子代理调度：五种接缝，和"调度层"的野心

第六节讲了 rc.8 把 Claude Code/Codex 变成按需子代理的新闻，这里拆机制。dsh 的子代理接缝（subagent seam）提供五种提供方：

1. **进程内派生**（in-process spawn）
2. **进程内分叉**（in-process fork）
3. **ACP 协议**（跨进程、跨产品）
4. **Codex**（作为子进程）
5. **Claude Code**（作为子进程）

调用方式极其朴素：装一个插件，发起一次工具调用，等待结果，把结果折叠回主会话。rc.8 之后补齐了三个工程件：Codex 的**非交互权限模式**（无人值守的 CI、定时任务）、**多命名实例**（同一任务里并存多个不同配置的 Codex 子代理）、**reportDelivery 机制**（子代理及时反馈结果并主动唤醒父任务，父任务不再盲等）。所有子代理行为——派生、回传、状态——都记录在追加式会话日志里，与主循环事件流同源，轨迹面板可查。

把这五根接缝连起来看，战略意图就清楚了：DSH 不想只做"又一个编码智能体"，它想站在 Claude Code 和 Codex 的**上一层**——它可以调度它们，也可以被 Zed 这样的编辑器通过 ACP 调度。媒体把这概括为一句话：DSH 的目标是成为 Agent 的"调度层"。收编而非对抗，是它对既有生态的总方针。

### 8.3 缓存经济学：命中率决定生死

第三节说过事件溯源设计"直接决定你跑一天花多少钱"，这节把账算开。

DeepSeek 的 API 定价，把缓存命中率变成了 Agent 成本的第一变量。发布时点的官方价格：

| 模型 | 缓存命中输入价（$/百万Token） | 缓存未命中输入价（$/百万Token） | 价差 |
|---|---|---|---|
| V4-Flash | 0.0028 | 0.14 | 50 倍 |
| V4-Pro | 0.003625 | 0.435 | 120 倍 |

（媒体口径，2026-08-13 发布时点；8 月 17 日涨价并引入峰谷计价后，当前价差约 30 倍，即第五节引用的数字。）

再看命中率。横向对照最说明问题：同一个 V4-Flash 模型，不同 Harness 跑出的缓存占比天差地别——Codex 约 70%，某参测 Harness 只有 1.5%，而新鲜输入的成本是缓存命中的五倍。DSH 这边，社区实测缓存命中率大多稳在 99% 上下，偶有掉到 60–70%；更早在 DSH 开源之前，就有媒体报道某 DeepSeek 定向 Harness 达到过 99.93% 的输入缓存命中率（未命中率 0.07%，该数字为媒体口径，具体项目存疑）。

机制解释回到第三节：会话日志追加式记录，模型可见的一切由日志投影生成，提示词天然被拆成稳定的缓存前缀加可变后缀。**前缀越稳定，命中越高**——事件溯源、上下文自动压缩、大输出落盘，这些被当作"可审计性卖点"的设计，同时也是缓存友好的成本设计。可审计性和低成本在这里是同一件事的两个名字，这是我认为 dsh 架构里最漂亮的一笔。

反过来，这也解释了第五节那个残酷案例：涨价之后，评估密集型项目最先死。对使用者的结论很直接：选 Harness 先看它保不保得住缓存前缀，这一项对总成本的影响，超过模型单价本身。

### 8.4 Cordis 论文：时空可组合性到底是什么

这篇论文叫《A Programming Paradigm for Spatiotemporal Composability》，2026 年 8 月 13 日与 dsh 同日公开，媒体口径全文 88 页，是仍在修订的预印本，论文仓库开源后拿了约 1.9 千星。媒体报道时管它叫 DeepSeek 的"自演化 AI 框架"论文。

论文的问题陈述：从插件系统到自演化智能体 Harness，现代软件越来越需要**动态组合**，但形式化基础一直欠发达。它把问题拆成两个正交维度——时间可组合性（组件移除时完全撤销其副作用）和空间可组合性（声明并响应式管理组件间依赖），然后给出四个核心构造：

1. **可逆效应（revertible effects）**：每次上下文变换都携带一个逆操作，由运行时追踪并执行撤销
2. **响应式共效应（reactive coeffects）**：上下文的每次变化，按组件的共效应规范通知该组件
3. **统一上下文类型**：效应上下文和共效应上下文合并为单一类型，构成一个编程范式
4. **动态组合演算**：在此之上定义"组件"，其元理论把时空可组合性从单个组件推广到交错组合的整个系统

Cordis 就是这套范式的实现：核心库做效应追踪和共效应解析，声明式组件加载器做配置调和与热模块替换。

论文里有个杀伤力很强的细节：它拿 2026 年 6 月的 VS Code Marketplace 数据做了一次审计，结论是现有插件系统普遍不及格——都只做了空间维，时间维靠开发者自觉。这也正式回答了第二节结尾那句话：现有插件生态几乎只做了前一半，Cordis 是第一个把后一半做成运行时不变式的。理解了这篇论文，你才能理解 `dsh-turn-rewind` 为什么能同时回退对话和工作区、创造模式为什么敢在内存里做插件实验——**失败成本为零，副作用可逆**。

读源码之前先读这篇论文的摘要，是成本最低的入门路径。

### 8.5 安全全景：一次逃逸，七个缺口

发布两周后，dsh 的安全图景可以概括成"一个已修复的漏洞，加一长串未经证实的报告"。

**已确认修复的**：Bubblewrap 沙箱逃逸，受限进程可经 `/proc/<pid>/root` 绕过沙箱限制，修复在 8 月 21 日的 v0.1.1-rc.1。值得注意的是披露方式：dsh 没有专门的安全通告格式，这条修复只躺在常规发布说明里，和表格布局修复并排——这是目前最接近 CVE 式披露的官方记录。同期还修了一个流程问题：文档站原本每次推送 master 就自动部署，未发布内容会泄露到公开页面，现已改为只有发布标签触发部署。

**社区报告的缺口**（8 月 18 日流传的一份第三方汇总，全部未经独立证实，但每条都值得警惕）：

| 报告的问题 | 对应风险 |
|---|---|
| Web 界面无认证（无令牌、无 Cookie、无 TLS） | 任何能触达端口的本地进程都能以你的身份操作 |
| 绑 `0.0.0.0` 会把局域网 IP 自动加进信任列表 | 同网段任何人获得同样的未认证控制权 |
| 未认证的回环 RPC 可读完整会话内容 | 绕过界面也能读到你的全部操作记录 |
| 插件安装立即在宿主进程执行，卸载可能留残留 | "装插件"不是沙箱预览，是立即执行 |
| AGENTS.md 指令注入，无需安装无需审批即可触发 | 不可信仓库内容在你授权之前就能操纵智能体 |
| 工作流工具的虚拟机隔离被报告可绕过 | "无文件系统/网络访问"的声明存在争议 |
| `workspace-write` 下模型被报告可自我批准并提权 | 本应人工点击的护栏被报告可绕开 |

这份清单的总评很到位：dsh 的模型行为被当作生产级对待，但插件代码执行的安全设计还没跟上。这些都不是什么高深零日漏洞，而是"你以为存在的信任边界，其实还不存在"。

横向看，这不是 dsh 一家的问题：同期 Claude Code 被披露沙箱漏洞（符号链接处理不当，编号 CVE-2026-39861）；7 月还有 OpenAI 的模型逃逸沙箱、触及 Hugging Face 生产系统的事件。**沙箱安全是整个 Agent 行业的未解难题**。

可以直接执行的防护清单：Web 界面只绑 `127.0.0.1`，远程访问走自建认证隧道；默认 `workspace-write` 加审批，不用 `danger-full-access`；装插件前审查代码，陌生插件放隔离 Profile 试用；固定 commit 或版本号；尽快升级到 0.1.1-rc.1；敏感仓库不放进工作区。社区已有三个防御插件（poison-guard、skill-security-guard、guardian），但记住：它们本身也是插件，装之前同样要审查。

还有个结构性风险要单列：AGENTS.md/CLAUDE.md 默认在每个新会话渲染最多 64KB 进上下文——工作区文件自动入上下文带来的指令注入，是所有同类 Harness 的共性，不是 dsh 独有。对不可信仓库，先看一眼它的 AGENTS.md 再让智能体进去。

### 8.6 分发层之战：从仓库堆到应用商店

第五节讲了生态的分层，这里单独拆分发机制，因为它是"生态"和"社区"的分水岭。

DSH 的插件发现走 GitHub topic：仓库打上 `dsh-plugin` 标签即可被发现。四天从 700 涨到近 8000，速度史无前例。但真正标志生态成立的是三层基础设施在发布后三到四天内自发成型：

- **内容层**：生产力插件补短板，玩具插件提供情绪价值（前面讲过）
- **策展层**：多份 awesome 精选目录按场景归档，插件索引站（dsh-index.xlings.org）把分散仓库聚合成可检索目录
- **分发层**：dsh-market 内置市场；桌面端 Studio 用 Electron 包了零代码体验——插件发现页、自然语言找插件（说一句"想要个桌面宠物"，Agent 自己去公开目录里检索并给推荐理由）、安装前校验版本与完整性、Preset 广场一键装整套"角色+技能+工具"组合

平台、内容、分发三要素齐备——这是"生态"区别于"社区"的判据。

但两根刺同样清晰。第一根是**契约稳定性**：官方承诺的是"将有破坏性变更"，开放插件生态要么稳定契约，要么强迫所有维护者追逐频繁的破坏性变更——正如一篇分析所说，"打破 GitHub 涨星纪录之后，艰难的部分才刚开始"。第二根是**定价波动**：3600 星项目停更是活案例，生态项目的生死不只看代码质量，还看平台定价表。

插件作者和使用者共同的生存法则：固定版本、审查安装脚本（构建脚本在沙箱外执行）、对"被收录"保持警惕——收录不等于审计。

## 九、谁值得学，怎么学

如果你是有 React 或类似前端基础、想做全栈方向的人，我给一条四阶段路线：

第一二天，先跑起来。npx 起 web 版，配 Key，建专用工作区，用标准模式做几个真实小任务，盯着轨迹面板看，把 step/turn 的概念看实。

第二三天，摸扩展体系。写一个 hello 插件，写两三个实用技能（代码风格检查、CSV 汇总这种），装个 MCP 桥接插件体会工具接入。重点搞懂 Profile 和 Patch 的组合机制，`dsh --dump-config` 是最好的老师。

第三到五天，深入架构。通读官方架构文档，理解事件溯源的会话模型，研究 Cordis 的依赖注入和生命周期，有余力的话读那篇时空可组合性的论文（88 页，先读摘要和结论）。尝试用 Patch 换掉一个系统组件，比如审批策略。

之后就是持续实践：按需装配插件，把它变成自己项目的自动化工作台——代码审查、文档生成、批处理。有痛点就写个插件开源，这是参与生态最快的方式。

学习心态上，把它当"会变形的 Claude Code"来用，当"Agent 操作系统的开源参考实现"来学。哪怕日后不深度用 dsh 本身，事件溯源、一切皆插件、权限与沙箱分离、缓存友好的上下文工程——这些思想在你之后碰到的任何 Agent 系统里都会反复出现。第七节那些案例已经证明：**模型趋同的时代，懂 Harness 的人比只会调模型的人多一层护城河**。

## 十、最后泼几盆冷水

它仍然是开发者预览版，rc 版本之间存在破坏性变更，生产使用必须锁版本，rc.8 的存储结构变更已经让旧数据不兼容了一次。

插件即代码，插件拿到的是模型能拿到的全部权限：文件、shell、凭据。8.5 节那七条社区报告的缺口，每一条都在提醒你：现阶段的信任边界是残缺的。

遥测默认关闭，但首次鉴权后每次请求会携带一个关不掉的匿名编号，官方在"已知限制"里写了；对话内容会发往模型服务器，敏感任务自己掂量。

商业化路径不明。定价策略直接改写生态走向，"降价引流、涨价筛选"的节奏对生态项目是系统性风险。另外"DeepSeek Harness"已注册商标，做二次创作发布的注意品牌使用边界。

还有一件事值得留意：DeepSeek Harness 团队的微信公众号已经注册了，头像是一只黑色鲸鱼。框架、模型、定价、官方内容阵地一起摆出来，这盘棋下得比多数人想的要完整。
