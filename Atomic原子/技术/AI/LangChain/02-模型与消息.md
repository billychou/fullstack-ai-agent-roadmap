# 02 - 模型与消息（Chat Models）

## 一、Chat Models：统一的模型抽象

LangChain 的核心抽象之一：**无论底层是 OpenAI、Anthropic、Gemini 还是本地 Ollama，调用方式完全一致**。换模型 = 换一行 import + 一行初始化。

```python
# 1.x 推荐：模型名直接传字符串，或用 provider 包初始化
from langchain_openai import ChatOpenAI
from langchain_anthropic import ChatAnthropic
from langchain_ollama import ChatOllama

# 三种模型，接口一模一样
openai_llm  = ChatOpenAI(model="gpt-4o")
claude_llm  = ChatAnthropic(model="claude-sonnet-4-6")
ollama_llm  = ChatOllama(model="llama3.2")  # 本地模型，零成本

llm = ollama_llm  # 切换只需改这一行
```

> 注：`create_agent(model="claude-sonnet-4-6")` 传字符串时，LangChain 会根据模型名前缀自动选择对应 provider 类（需要已安装对应包）。

## 二、消息（Message）：模型对话的"语言"

所有 Chat Models 的输入输出都是**消息列表**，消息有 4 种角色：

| 消息类型 | 含义 | 用途 |
|---|---|---|
| `SystemMessage` | 系统指令 | 设定角色、规则、约束（最高优先级） |
| `HumanMessage` | 用户输入 | 用户的提问/指令 |
| `AIMessage` | 模型输出 | 模型生成的回答；也承载工具调用请求 |
| `ToolMessage` | 工具结果 | 工具执行后返回给模型的结果 |

**基础调用：**

```python
from langchain_core.messages import SystemMessage, HumanMessage

messages = [
    SystemMessage("你是一个精通 Python 的资深工程师，回答要简洁"),
    HumanMessage("请用一句话解释什么是装饰器"),
]

resp = llm.invoke(messages)   # 返回 AIMessage
print(resp.content)           # 模型文本
print(resp.tool_calls)        # 若模型要求调用工具，这里会有调用列表
```

## 三、Prompt Templates：把提示词变成可复用模板

```python
from langchain_core.prompts import ChatPromptTemplate

# 方式一：最常用，字符串模板 + 变量
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个{role}，请用{language}回答"),
    ("human", "{question}"),
])

# 渲染模板
filled = prompt.invoke({
    "role": "Python 专家",
    "language": "中文",
    "question": "解释一下生成器",
})
# filled 此时就是一个消息列表，可直接喂给模型
```

**关键设计思想**：Prompt 模板与模型解耦 —— 同一个模板换模型、换参数就能复用；这也是后续做提示词管理（LangSmith Prompt Hub）的基础。

**组合用法（模板 + 模型 = Runnable 管道）：**

```python
chain = prompt | llm          # 管道符组合，1.x 保留的优雅写法
result = chain.invoke({"role": "Python 专家", "language": "中文", "question": "什么是闭包"})
```

## 四、工具调用（Tool Calling）：Agent 的基石

要让模型"学会调用工具"，核心是 `bind_tools` —— 把工具的 JSON Schema 绑定给模型，模型就会在需要时返回 `tool_calls` 而**不是直接回答**。

```python
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """计算两个整数之和"""
    return a + b

# 1. 绑定工具到模型
llm_with_tools = llm.bind_tools([add])

# 2. 模型感知到需要计算时，会返回工具调用请求
resp = llm_with_tools.invoke([HumanMessage("3 加 5 等于多少？")])
print(resp.tool_calls)
# [{'name': 'add', 'args': {'a': 3, 'b': 5}, 'id': 'call_xxx'}]

# 3. 执行工具，把结果作为 ToolMessage 喂回模型
import json
from langchain_core.messages import ToolMessage

result = add.invoke(resp.tool_calls[0]["args"])
messages = [
    HumanMessage("3 加 5 等于多少？"),
    resp,                              # AIMessage（带 tool_calls）
    ToolMessage(content=str(result), tool_call_id=resp.tool_calls[0]["id"]),
]
final = llm_with_tools.invoke(messages)
print(final.content)  # "3 + 5 = 8"
```

> 这套「模型出调用请求 → 执行工具 → 结果喂回」的循环，正是 `create_agent` 内部自动帮你完成的。理解这一步，就理解了 Agent 的本质。

## 五、结构化输出：让模型按 Schema 返回

业务系统需要的是 JSON，不是散文。用 Pydantic 定义输出结构：

```python
from pydantic import BaseModel, Field
from langchain_core.messages import HumanMessage

class WeatherInfo(BaseModel):
    city: str = Field(description="城市名")
    temperature: float = Field(description="摄氏温度")
    condition: str = Field(description="天气状况，如晴/雨/多云")

# 绑定输出 schema，模型会强制按此结构返回
structured_llm = llm.with_structured_output(WeatherInfo)

res = structured_llm.invoke([HumanMessage("北京现在多少度？")])
print(res)             # WeatherInfo(city='北京', temperature=28.5, condition='晴')
print(res.temperature) # 直接是 Pydantic 对象，类型安全
```

**实现原理**：`with_structured_output` 底层就是 JSON Schema + `bind_tools`（或 JSON mode），把 schema 传给模型，再把返回解析成 Pydantic 对象。这是生产代码里最常用的能力之一。

for chunk in llm.stream(messages):

## 七、本节小结

| 能力 | API | 一句话 |
|---|---|---|
| 模型统一接口 | `ChatOpenAI` 等 | 换模型只改一行 |
| 消息 | 4 种 Message 类型 | 模型对话的输入输出格式 |
| 模板 | `ChatPromptTemplate` | 提示词可复用、可管理 |
| 工具调用 | `bind_tools` + `@tool` | Agent 决策的基础 |
| 结构化输出 | `with_structured_output` | 业务可消费的 JSON |
| 流式 | `stream` / `astream` | 打字机效果 / 异步 |
