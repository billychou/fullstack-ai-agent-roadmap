# 01 - 生态全景与 1.0 重构

## 一、三件套的关系（最重要的认知）

```
┌─────────────────────────────────────────────────┐
│  LangSmith（商业）：Trace / 评测 / 部署 / 提示词管理  │  ← 上线必备
├─────────────────────────────────────────────────┤
│  LangGraph（开源）：状态图编排运行时                   │  ← 生产编排层
│   - StateGraph / Checkpoint / HITL / 持久化        │
├─────────────────────────────────────────────────┤
│  LangChain（开源）：高层 Agent 框架                  │  ← 快速开发层
│   - create_agent / 模型抽象 / 工具 / Prompt         │
│   - 底层就是跑在 LangGraph 上                       │
└─────────────────────────────────────────────────┘
```

**一句话总结**：LangChain 是"开箱即用的 Agent 工厂"，LangGraph 是"可编程的状态机运行时"，LangSmith 是"生产运维平台"。三者不是并列关系，而是 上→下 的依赖关系。

## 二、为什么会有 1.0 重构（背景）

LangChain 0.x（2022-2025）的痛点：
- **抽象臃肿**：Chains、Agents、Memory 等多套抽象并存，同一个功能有五六种写法
- **API 频繁变动**：教程写出来几个月就失效，社区怨声载道
- **生产乏力**：线性 Chains 无法表达循环、分支、人工介入等真实场景

**2025-10 发布的 1.0 是"定位重置"而非小版本升级：**
- 旧抽象（LLMChain、ConversationBufferMemory、initialize_agent 等）整体迁入 `langchain-classic` 包，向后兼容但不再演进
- 核心收敛为一个原语：`create_agent`
- 承诺：1.x 到 2.0 之前无破坏性变更（API 终于稳定）

## 三、1.0 的十行 Agent（新世界观）

```python
from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """Get weather for a given city."""
    return f"It's always sunny in {city}!"

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[get_weather],
    system_prompt="You are a helpful assistant",
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What's the weather in San Francisco?"}]}
)
```

关键点：
- 模型名直接传字符串（1.x 内部自动解析到对应 provider）
- 工具就是**普通 Python 函数**，`@tool` 装饰器让它可被模型发现
- 输入/输出都是标准消息列表 `{"messages": [...]}`
- 这一个 `create_agent` 内部构造了一个完整 LangGraph 图（ReAct 循环）

## 四、什么时候用哪一层（选型决策）

| 场景 | 推荐层 | 理由 |
|---|---|---|
| 快速原型 / 标准问答 Agent | LangChain `create_agent` | 十行搞定，够用 |
| 自定义流程 / 状态机（循环、分支） | LangGraph | 需要显式控制执行流 |
| 长任务 / 崩溃恢复 / 断点续跑 | LangGraph + Checkpointer | durable execution |
| 需要人工审批环节 | LangGraph `interrupt()` | HITL 一等公民 |
| 多 Agent 协作 | LangGraph（Supervisor/Swarm） | 状态共享与调度 |
| 生产监控 / 评测 / 部署 | LangSmith | Trace + Eval + Deploy |
| 极简场景（1 模型 1 工具无状态） | 裸 Python | 不上框架更清晰 |
