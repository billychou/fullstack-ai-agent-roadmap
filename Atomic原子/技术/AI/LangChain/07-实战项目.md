# 07 - 实战项目（把知识变成能力）

> 前置：学完 [[00-学习大纲|大纲]] 阶段一~六。**没有项目，笔记就只是笔记。** 以下是四个递进项目，建议至少完成前三个。

## 项目 A：企业知识库问答机器人（RAG + 引用溯源）

**目标**：基于公司文档回答员工问题，答案带来源引用，检索不到明确说明。

**技术栈**：[[04-RAG检索增强生成]] 全部 + LangServe 部署

**功能清单**：
- [ ] 文档上传（支持 PDF / Markdown / Word）
- [ ] 自动切分 + 向量化 + 入库（增量更新）
- [ ] 问答 + 引用溯源（答案底部标注来源文档与页码）
- [ ] 检索不到时说"资料中未提及"，不编造
- [ ] 流式输出
- [ ] （进阶）多轮对话追问；Hybrid Search 提升专有名词命中

**验收标准**：30 份真实文档入库，10 个典型问题命中率 ≥ 80%，答案全部可溯源。

## 项目 B：多工具个人助理（Agent + 工具）

**目标**：一个能查天气、查汇率、管理待办、定闹钟的语音/文字助理。

**技术栈**：[[03-工具与Agent]] + 记忆 + LangSmith

**功能清单**：
- [ ] 4+ 个工具：天气查询、汇率换算、待办清单（增删查）、纪念日提醒
- [ ] 多轮对话记忆（Checkpointer + thread_id 按用户隔离）
- [ ] 关键操作（删待办）需确认后才执行
- [ ] LangSmith 追踪 + 简单评测集
- [ ] （进阶）接入 MCP 生态工具（见 [[W05-MCP协议详解]]）

**验收标准**：连续对话 10 轮不丢上下文；"帮我加个待办：周五交周报"这类自然语言指令 100% 正确执行。

## 项目 C：客服工单多 Agent 系统（LangGraph + HITL）

**目标**：客服工单自动分类、处理、升级，关键操作人工审批。

**技术栈**：[[05-LangGraph运行时]] 全部（图 + Checkpointer + interrupt + 多 Agent）

**架构设计**：
```
用户提交工单
   │
   ▼
[分类Agent] ──> 退款 / 技术支持 / 投诉  (条件分支)
   │
   ├─ 退款  ──> [退款Agent] ──> interrupt() 人工审批金额 ──> 执行
   ├─ 技术支持 ──> [技术支持Agent]（可调用知识库 RAG 工具）
   └─ 投诉  ──> [升级流程]（转人工经理队列）
```

**功能清单**：
- [ ] StateGraph 工单状态机（待处理 → 处理中 → 已完成/已升级）
- [ ] 分类 Agent + 处理 Agent 分工
- [ ] 退款超过阈值时 interrupt() 暂停等审批
- [ ] Checkpointer 持久化工单状态，支持中途断线恢复
- [ ] 工单历史可回放（LangSmith time-travel）

**验收标准**：模拟 50 张工单，分类准确率 ≥ 90%；退款审批流程从提交到完成全程可追踪、可回放。

## 项目 D：结合 MCP 的 Agent（生态扩展，选做）

**目标**：通过 MCP 协议接入第三方工具生态（GitHub、数据库、企业系统）。

**要点**：
- MCP = Model Context Protocol，Agent 连接外部世界的标准协议（[[W05-MCP协议详解]]）
- LangChain 1.x 对 MCP 有官方支持，可将 MCP 服务作为工具接入 `create_agent`
- 与自写工具对比：MCP 适合"现成服务"，自写工具适合"内部逻辑"

## 项目验收通用清单（每个项目都过一遍）

- [ ] LangSmith 全程可观测，每个节点输入输出可见
- [ ] 有 20+ 条评测集和回归跑分
- [ ] 关键操作有安全护栏（审批/权限/注入防护）
- [ ] 有错误处理（LLM 调用失败、工具异常、超时重试）
- [ ] 有 README：架构图 + 运行方式 + 已知限制
- [ ] 沉淀到本目录：项目复盘笔记（遇到什么坑、怎么解决）
