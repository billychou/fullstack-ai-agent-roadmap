
> **一句话记住**：HEAD 就是 Git 里的"书签"🔖，标记着你当前正在看哪一页

---

## 用一本书来理解

把 Git 仓库想象成一本**历史书**，每个提交是书中的一页：

```
第1页 ← 第2页 ← 第3页 ← 第4页 ← 第5页
                                ↑
                              🔖 HEAD（你正看到这页）
```

- **翻页**（`git checkout`）= 移动书签到另一页
- **写新内容**（`git commit`）= 在当前页后面加一页，书签自动跟到新页
- **书签本身不是内容**，它只是一个标记位置的东西

---

## 两种状态

### ✅ 正常状态：书签夹在章节名上

HEAD 指向一个**分支名**（比如 `main`），分支名再指向最新的那页。

```
        🔖 HEAD
          ↓
        main
          ↓
第1页 ← 第2页 ← 第3页
```

你写新内容时，`main` 和书签一起往前移。**这是日常开发的状态。**

### ⚠️ 分离状态：书签直接夹在某页上

HEAD 直接指向某一页，不通过任何章节名。

```
   🔖 HEAD
      ↓
第1页 ← 第2页 ← 第3页
                  ↑
                 main
```

通常是你执行了 `git checkout <某个旧提交>` 触发的。

**风险**：这时候你写的新内容没有章节名记录，一旦你把书签挪走，新写的页数就可能丢失。

**补救**：赶紧给当前页起个章节名 → `git branch temp-save`

---

## HEAD 能帮你做什么

|你想做的|怎么用 HEAD|
|---|---|
|看当前在哪|`git log`（默认从 HEAD 开始）|
|看上一页|`HEAD~1`|
|看上上页|`HEAD~2`|
|回到3页前|`git reset --hard HEAD~3`|
|比较当前页和手头的改动|`git diff`（默认对比 HEAD）|

> 💡 `HEAD~1` 就是"书签往回挪一格"的意思，不用记哈希值。

---

## 三个常见误解

|误解|真相|
|---|---|
|HEAD 是一个提交|❌ 它只是个指针/书签|
|分离 HEAD 会丢代码|❌ 代码还在，只是没分支名指着，及时建分支就行|
|每个仓库只有一个 HEAD|❌ 用了 worktree 的话，每个工作目录有自己的 HEAD|
